# Tavus private pilot API contract

Research snapshot: 15 October 2026. Source: [official OpenAPI](https://docs.tavus.io/openapi.yaml), [PAL LLM configuration](https://docs.tavus.io/sections/conversational-video-interface/pal/llm), [create PAL](https://docs.tavus.io/api-reference/pals/create-pal), [create conversation](https://docs.tavus.io/api-reference/conversations/create-conversation). These are implementation notes, not evidence of a completed provider trial.

- Current resources are `POST /v2/pals` and `POST /v2/conversations` at `https://tavusapi.com`, authenticated with `x-api-key`. Use `pal_id`, `face_id`/`default_face_id`, and `languages: ["el"]`, rather than older persona/replica/language aliases.
- A new PAL per app session binds its custom LLM to a session-specific secret. The custom LLM uses an OpenAI-compatible `/chat/completions` endpoint with SSE. `layers.llm.base_url` excludes that endpoint suffix; `api_key` supplies its bearer credential. No real provider API key is sent as this credential. The callback must validate the session secret and serve only completely verified application replies.
- Full CVI is selected, speculative inference is off, and no tools, MCP connectors, objectives, external knowledge documents or persistent participant tags are attached. Perception is explicitly off. Spoken and visible AI disclosures are fixed Greek text. Dynamic greetings and idle engagement are off. The fixed opening contains no product claims. Product answers all pass through the custom LLM callback.
- Sessions request `require_auth: true`, maximum two participants (shopper and avatar), 180-second maximum duration, and 30-second absent/left timeouts. The official schema declares no minimum for those timeout properties. There is no documented idle-shutdown property: the application must enforce any additional idle rule itself.
- `enable_recording: false` and `auto_start_recording: false` disable recording controls/automatic recording. The schema does **not** expose a transcript-persistence disable switch. Do not claim that Tavus keeps no transcript. Provider retention, deletion, and account processing terms must be verified before broader visitor exposure. No app analytics or logs may contain transcripts, audio, callback credentials, meeting tokens or join URLs.
- `policy: "eu"` controls specific emotion/disclosure defaults; it does **not** establish EU data residency. Perception remains off and disclosure is explicitly enabled regardless of those defaults.
- The client accepts only the documented `https://tavus.daily.co/<room>` origin/path and a bounded syntactic JWT returned separately. This validates transport structure, not the provider's JWT signature; Daily validates admission. Pass the token separately to Daily's `join()` rather than including it in a browser URL. Other Daily subdomains require explicit provider verification before allowlisting.
- No retries for create requests: a timeout may have created a remote object. The application must retain known resource IDs for cleanup; unknown outcomes require reconciliation before another attempt. `POST /v2/conversations/{id}/end` ends routine calls. `DELETE /v2/conversations/{id}` removes conversation data; `?hard=true` is an explicitly destructive choice, never implicit in ordinary end. A session-created PAL should be deleted after termination. Maximum duration bounds an orphaned conversation but does not delete its PAL or provider data.
- `test_mode: true` validates conversation creation, creates an ended session, and never joins the avatar. It is not a voice, latency, safety, Greek pronunciation or spending test. Live testing still needs valid Tavus account access, a selected available face, and plan/credit confirmation.

The local adapter has injectable transport, fixed API origin, redirect refusal, bounded response bytes and deadlines, cancellation, strict response allowlisting, and generic failure messages. These checks are covered with mocked provider responses; they cannot establish real provider behavior.
